# Haptics Implementation Plan

**Goal:** Implement the approved three gameplay cues and an independent saved haptics preference.

**Architecture:** A small optional browser controller coalesces synchronous cues, gives results priority, cancels on hide/navigation, and never retries refused vibration. Gameplay arms result feedback only after an accepted choice; existing snapshot event tracking prevents replay. The contact header contains a separate accessible toggle, hidden when the API is absent.

**Tech Stack:** Vanilla JavaScript, navigator.vibrate, localStorage, node:test, Playwright Chromium/WebKit.

## Approved design

- Accepted gameplay answer: 8 ms. Visible successful story outcome: [12, 55, 12] ms. Visible story/run failure: 35 ms.
- A synchronous result replaces the answer cue. Deferred defeat waits for the existing visible defeat reveal.
- No per-message, navigation, blocked-action, restored-state, rerender or hidden-page feedback. No second victory cue on the congratulations modal.
- Preference `mistakery.haptics` is independent of sound and defaults on where the API exists. Unsupported/refused calls never affect gameplay or trigger a workaround.
- Keep existing release checkout/PR, original dimensions, saves and Safari audio behavior. Preserve untracked experiments.
