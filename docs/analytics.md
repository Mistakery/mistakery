# Gameplay analytics

The game sends explicit events directly to PostHog's public [Capture API](https://posthog.com/docs/api/capture). No SDK, autocapture, session recording, extra game UI or backend is installed. Delivery never blocks play or saving.

## Connection

`assets/analytics-config.js` contains the public Project API key and US Cloud ingestion host. The project is configured for **US Cloud**, as confirmed by the owner, even though EU was initially selected during signup. A `integration_test` event was accepted by `https://us.i.posthog.com/i/v0/e/` on 2026-10-19 (HTTP 200, `status: Ok`). Dashboard visibility and delivery from a real published itch embed still need verification. No game build was published during setup.

Collection runs only on HTTPS `*.itch.zone` embeds or exact release origins explicitly listed in `allowedOrigins`. localhost, file launches and Cloudflare/GitHub previews are excluded by default. `?test=route`, `?story=live-agent`, and `?preview=losses` always disable it. Setting `enabled: false` disables collection everywhere. After editing config, rebuild runtime hashes with `node scripts/build-offline-deck.cjs`.

To find the public key: PostHog Settings → Project → Project variables. Use the `phc_…` Project API key, never a personal API token. The host must match the actual project region: US `https://us.i.posthog.com`, EU `https://eu.i.posthog.com`. For a new account, PostHog creates Default Project automatically; rename it in the project settings.

## Events

| Event | Trigger | Main properties |
| --- | --- | --- |
| `game_opened` | Normal game bootstrap, including reload | `has_save` |
| `game_started` | First-entry Tap to play | — |
| `intro_completed` | Last Saved reply starts the first playable card | Run properties |
| `run_started` | First attempt or explicit New run | `source` (`intro`/`new_run`), `card_id` |
| `run_resumed` | Continue on the title | `turn`, `card_id` |
| `choice_made` | Accepted gameplay decision | `card_id`, `story`, `side`, `turn`, `next_card_id` |
| `story_completed` | Outcome acknowledged; Judgment Day instead ends immediately on entry | `story`, `outcome`, `first_win`, `turn` |
| `run_ended` | Route ends in resource defeat, Judgment Day or three completed stories | `ending`, `turn`, `stories_completed` |
| `ceo_unlocked` | First collected win in the third distinct story | `ceo_type`, `turn` |
| `integration_test` | Setup smoke test only; not generated by the game | `test: true` |

Every event has a random browser `distinct_id`, event UUID, timestamp, `game_build`, and a page-load `session_id`. Run events also have `run_id` and `attempt_number`. `run_id` uses the saved attempt's identity when storage is available. IDs do not alter the seeded game RNG.

`story_completed` means the outcome was acknowledged, not merely displayed (except terminal Judgment Day). A successful story may still end the company at the resource settlement boundary. CEO unlock follows cumulative first victories, not the number of successes in this one attempt. Showing/revealing an already earned card sends no new unlock.

## Useful views in PostHog

- **First entry funnel:** `game_opened` filtered to `has_save=false` → `game_started` → `intro_completed`. Count unique users, not total events. Reloads can produce several opens for one browser.
- **Attempts and replay:** count `run_started`; break down by `attempt_number` or `source`.
- **Story outcomes:** `story_completed`, breakdown by `story` and `outcome`; filter `first_win=true` for new persistent victories.
- **CEO completion:** unique users with `ceo_unlocked`; break down by `ceo_type` and `attempt_number`.
- **Where attempts stop:** inspect the last `choice_made` per `run_id`, including `next_card_id`, and whether that run has `run_ended`. This is an exit proxy, not proof of quitting: players can return and Continue later. For attempts with no decisions, use `run_started.card_id`.

Exclude `integration_test` from player reports. No dashboards were created automatically; doing that needs access to the PostHog UI or a separately authorized management API.

## Reliability and privacy

- `mistakery.analytics` is a separate localStorage record: random browser ID, observed attempt count, first-CEO marker and last accepted turn for up to 16 recent attempts. Game progress stays in `mistakery.browser-save`.
- Restore baselines already saved history without backfilling events. Continue, rerender and reward reveal cannot resend decisions, story results or CEO unlocks. Detected stale-tab writes do not emit choice events.
- Attempt numbers count attempts observed since analytics was enabled; they are not a lifetime total for existing players. Browser/device/origin changes or storage clearing create separate identities. When storage fails, identity/deduplication are only available in memory and may reset after reload or storage recovery.
- Requests are best effort, without retries or a persistent network queue. Offline play, ad blockers, browser shutdown and network errors can drop events. A successful API response confirms acceptance, not dashboard indexing. Analytics failure cannot stop play or saving.
- No names, emails, page URLs, referrers, message text or DOM content are added. Person profiles are disabled with `$process_person_profile: false`, and GeoIP enrichment with `$geoip_disable: true`. Browser DNT/GPC disables collection; setting `mistakery.analytics.opt-out` to `1` takes effect on the next load. Requests omit cookies/credentials and referrer headers. PostHog still receives the network request.

## Verification

`npm run test:unit` includes analytics identity, duplicate suppression, privacy gates and failure isolation. `node --test tests/analytics.browser.test.cjs` checks Chromium and WebKit: intro, decisions, reload/Continue, new attempt, CEO unlock, terminal loss, stale tabs, QA isolation, inactive release origins and failed requests. All browser test traffic is intercepted locally; it cannot reach the real project. Sound is off before page load.
